## Issue 1

### Title

`feat: ファイル単位でノートを取り込めるようにする`

### Body

```md
## 概要

コピペだけでなく、ファイルを選択して SaiKai にノートを取り込めるようにしたいです。

現状は会話本文を貼り付ける前提ですが、学習メモや保存済みの会話ログをそのまま扱いたいケースがあるため、ファイル入力に対応したいです。

## 目的

- コピペの手間を減らす
- 保存済みテキストをそのまま取り込めるようにする
- 今後の講義ノート対応や多様な入力ソースへの拡張の土台を作る

## 想定スコープ

- MVP として `.txt` / `.md` の取り込みに対応する
- 取り込み画面にファイル選択 UI を追加する
- 読み込んだファイル内容を、既存の前処理・ノート化フローへ流す
- 既存ノートの続きとして Session 追加する流れでも使えるようにする

## 受け入れ条件

- ユーザーが `.txt` または `.md` ファイルを選択して取り込める
- 既存の貼り付け取り込みと同じように保存前プレビューへ進める
- ファイル読込エラー時に分かりやすいメッセージが表示される
- 既存の貼り付け取り込み UX を壊していない

## 補足

将来的には PDF や画像 OCR に拡張したいが、この Issue では対象外とする。
```

## Issue 2

### Title

`feat: AIチャット以外の講義ノートや人間のメモも取り込めるようにする`

### Body

```md
## 概要

SaiKai は現在 AI チャット整理が中心ですが、講義ノートや人間が書いたメモも取り込めるようにしたいです。

AI チャットだけでなく、人間のノートも「外部 LLM が文脈を把握しやすい再開可能ノート」に変換できるようにするのが目的です。

## 目的

- AI チャット以外の入力ソースにも対応する
- 講義ノートや学習メモを SaiKai 上で蓄積できるようにする
- 外部 LLM に渡しやすい文脈情報へ整形できるようにする

## 想定スコープ

- 取り込み種別として `AIチャット / 講義ノート / 自由メモ` を追加する
- 人間のノート向けに、話者分離ではなく `主題 / 要点 / 用語 / 疑問点` を抽出する
- 再開プロンプトで「講義ノート由来の内容」であることを前提として渡せるようにする
- Session として継続蓄積できる形を保つ

## 受け入れ条件

- AI チャットでないテキストも取り込める
- 講義ノートや自由メモから、SaiKai のノート構造へ落とし込める
- 再開ページで、その内容を元に再開用プロンプトを作れる
- 既存ノートに人間のメモ由来 Session を追加できる

## 補足

この Issue は「入力ソースの拡張」が主題であり、数学専用の整理は別 Issue で扱う。
```

## Issue 3

### Title

`refactor: 取り込み種別ごとに前処理と生成方針を切り替えられるようにする`

### Body

```md
## 概要

今後、AIチャット、講義ノート、数学ノートなど複数の入力ソースに対応するため、前処理と要約方針を種別ごとに分けやすい構造へ整理したいです。

現在は処理の入り口が比較的共通化されていますが、将来的な拡張を見据えると、入力種別ごとに分岐点を明確にした方が保守しやすいです。

## 目的

- 今後の入力ソース追加をしやすくする
- UI 層に条件分岐が散らばるのを防ぐ
- 数学モードや講義ノート対応の土台を作る

## 想定スコープ

- 取り込み種別の type / enum を整理する
- preprocess 層と generation 層の分岐点を明確にする
- AIチャット / 講義ノート / 数学モード で切り替えやすい構成にする
- 将来的な PDF / OCR / 数式特化処理を差し込みやすくする

## 受け入れ条件

- 入力種別に応じて前処理方針を切り替えられる
- 入力種別に応じて生成方針を切り替えられる
- UI に過度な if 分岐が増えず、lib 側で整理されている
- 今後のモード追加時に既存フローを壊しにくい構造になっている

## 補足

この Issue は新機能追加よりも、将来拡張しやすくするための整理が中心。
```

## Issue 4

### Title

`feat: 複雑な計算や論理展開を整理しやすい数学モードを実装する`

### Body

```md
## 概要

複雑な計算や高度な論理展開でも、SaiKai 上で崩れにくくノート化できる「数学モード」を実装したいです。

通常の要約では、定義・途中式・証明の流れ・結論の関係が潰れやすいため、数学向けの専用整理モードが必要です。

## 目的

- 数学や理論系の長い対話を扱いやすくする
- 計算過程や論理の流れを保ったまま整理する
- 再開時に「どこまで理解できたか」「どこで詰まっているか」を明確にする

## 想定スコープ

- 取り込み時に `数学モード` を選べるようにする
- 要約構造を `前提 / 定義 / 計算の流れ / 結論 / 未解決点` に寄せる
- 数式や改行構造をできるだけ保つ前処理を追加する
- 再開プロンプトに `途中式を省略しすぎない` `論理を飛ばさない` などの指示を反映しやすくする

## 受け入れ条件

- 数学系テキストを通常モードより崩れにくく整理できる
- 計算の途中や論理の分岐が追いやすい形でノート化される
- 再開時に前提や途中式を踏まえたプロンプトが作れる
- 未解決点が通常モードより数学向けに抽出される

## 補足

初期実装では数式レンダリングまでは必須とせず、まずは整理構造と再開しやすさを優先する。
```

## Issue 5

### Title

`feat: 再開プロンプト生成でソース種別に応じた文脈付けを行う`

### Body

```md
## 概要

再開用プロンプト生成時に、AIチャット由来か、講義ノート由来か、数学モード由来かで、文脈付けや指示の組み立てを変えられるようにしたいです。

同じ要約でも、元データの性質によって外部 LLM に渡すべき前提が変わるため、再開プロンプト側の最適化が必要です。

## 目的

- 再開プロンプトの質を上げる
- 外部 LLM が前提を取り違えにくいようにする
- 入力ソースごとに自然な再開文脈を作れるようにする

## 想定スコープ

- ノートや Session に source context を持たせる
- 再開ページでソースに応じた補助文を自動挿入する
- 数学モード時は `途中式を保つ` `論理を省略しない` などを優先しやすくする
- 講義ノート時は `講義内容を踏まえて` という前提を自然に渡せるようにする

## 受け入れ条件

- ソース種別ごとに再開プロンプトの質感が変わる
- AIチャット由来 / 講義ノート由来 / 数学モード由来で前提の置き方が変わる
- 外部 LLM が文脈を誤読しにくくなる
- 既存の再開ページ UX を大きく壊していない

## 補足

この Issue はプロンプト生成 UX の改善が中心であり、入力ソースの追加そのものは別 Issue で扱う。
```

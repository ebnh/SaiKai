# GitHub 公開メモ

## About 欄の説明文

### 短め

AIチャットや講義メモを、再開しやすい文脈ノートに整理して蓄積するアプリ

### 少し詳しめ

SaiKai は、AIチャットやノートを「再開しやすい対話ノート」に整理・保存し、外部 LLM との対話を文脈つきで続けやすくするアプリです。

## Issue ロードマップ

### 1. ファイル単位でノートを取り込めるようにする

- Title:
  `feat: ファイル単位でノートを取り込めるようにする`
- Goal:
  コピペではなく、テキストファイルや将来的なドキュメントファイルから SaiKai に内容を取り込めるようにする。
- Scope:
  - MVP として `.txt` / `.md` を対象にする
  - 取り込み画面にファイル選択 UI を追加する
  - 読み込んだ内容を既存の前処理・ノート生成フローへ流す
  - セッション追加フローでもファイル取り込みを使えるようにする
- Done when:
  - ユーザーがファイルを選んで取り込める
  - 既存の貼り付け取り込みと同じように保存前プレビューへ進める
  - エラー時に分かりやすいメッセージが出る

### 2. 数学モードを実装する

- Title:
  `feat: 複雑な計算や論理展開を整理しやすい数学モードを実装する`
- Goal:
  数式、計算過程、定義、証明の流れを崩さずに整理できる専用モードを追加する。
- Scope:
  - 取り込み時に「数学モード」を選べるようにする
  - 要約を「前提 / 定義 / 計算の流れ / 結論 / 未解決点」に寄せる
  - 改行や式の構造をできるだけ保つ前処理を追加する
  - 再開プロンプトでも「途中式を省略しない」などの指示を組み込みやすくする
- Done when:
  - 数学系の会話やノートが通常モードより崩れにくく整理される
  - 計算の途中や論理の分岐が追いやすい形でノート化される
  - 再開時に「前回どこまで分かったか」を自然に引き継げる

### 3. 講義ノートや人間のノートも取り込めるようにする

- Title:
  `feat: AIチャット以外の講義ノートや人間のメモも取り込めるようにする`
- Goal:
  AI との対話だけでなく、人が書いた講義ノートや学習メモも SaiKai に取り込み、外部 LLM が文脈を把握しやすい形へ整理できるようにする。
- Scope:
  - 取り込み種別として「AIチャット / 講義ノート / 自由メモ」を追加する
  - 人間のノート向けに、話者分離ではなく「主題 / 要点 / 用語 / 疑問点」を抽出する
  - 再開プロンプトで「これは講義ノート由来の内容です」と前提を渡せるようにする
  - Session として継続蓄積できる形を保つ
- Done when:
  - AI チャットでないテキストでも自然に取り込める
  - 外部 LLM に渡すための再開用文脈が作れる
  - 既存ノートに人間のメモ由来 Session を追加できる

### 4. 取り込み種別ごとに前処理と要約方針を分ける

- Title:
  `refactor: 取り込み種別ごとに前処理と生成方針を切り替えられるようにする`
- Goal:
  今後の拡張に備えて、AIチャット、数学ノート、講義ノートで処理の入り口を分けやすくする。
- Scope:
  - 取り込み種別の enum / type を整理する
  - preprocess 層と generation 層の分岐点を明確にする
  - 将来の PDF / 画像 OCR / 数式特化処理の差し込み口を用意する
- Done when:
  - 条件分岐が UI にベタ書きされず、lib 側で整理されている
  - 種別追加時に既存フローを壊しにくい構造になる

### 5. 再開プロンプトでソース種別を意識した文脈生成を行う

- Title:
  `feat: 再開プロンプト生成でソース種別に応じた文脈付けを行う`
- Goal:
  AIチャット由来か、講義ノート由来か、数学モード由来かで、再開プロンプトの組み立てを最適化する。
- Scope:
  - ノートや Session に source context を持たせる
  - 再開ページでソースに応じた補助文を自動挿入する
  - 数学モード時は「途中式を保つ」「論理を省略しない」などを優先しやすくする
- Done when:
  - ソースごとに再開プロンプトの質感が変わる
  - LLM が前提の取り違えをしにくくなる

## 推奨順

1. ファイル単位でノートを取り込めるようにする
2. 講義ノートや人間のメモも取り込めるようにする
3. 取り込み種別ごとの前処理・生成方針を分ける
4. 数学モードを実装する
5. 再開プロンプトでソース種別を意識した文脈生成を行う
